# Domain documentation

This repository has one domain context: `GLOSSARY.md` at the root and `docs/adr/`.

Before working on an area, read the glossary entries and ADRs relevant to it. Use the glossary's terms in code, tests, issues, documentation and proposals; do not use the synonyms listed under _Avoid_.

If a needed concept is missing from the glossary, settle the terminology with the developer and add it rather than inventing a parallel term. If a proposal contradicts an existing ADR, surface that explicitly and reopen the decision rather than silently overriding it.
